# Deployment and incident runbook

## Before any AWS apply

Obtain access only now: target AWS account/region, repository/environment, approved agent package and policy owner, DNS/certificate owner, VPC and subnet IDs, restricted caller CIDRs, budget recipient and secret ARNs. No secrets should be pasted into tickets or committed. Create API token directly in Secrets Manager; Terraform only references its ARN. Customer KMS keys require an additional scoped decrypt grant. Provider secrets need separate scoped mappings and grants after adapter review.

This module consumes an existing VPC: at least two ALB public subnets in different AZs, private task subnets with approved HTTPS egress (NAT or endpoints plus model access), DNS resolution and routing. HTTPS egress is broad in this scaffold; restrict via approved proxy/endpoints for production. NAT and ALB can dominate idle costs. No autoscaling is configured; one task is an initial staging choice, not production HA. Production requires measured sizing, at least two tasks across AZs and a capped scaling policy. Canary temporarily runs both revisions and costs more.

Bootstrap a versioned encrypted S3 state bucket with access controls and locking. Run `terraform init -backend-config=...` using the reviewed remote backend configuration, `terraform fmt -check`, `terraform validate`, then `terraform plan -out=tfplan`. Independently review resource changes and estimate fixed and usage costs; only then apply the saved plan. Activate the project cost allocation tag; until active, use an account-level budget too. Budget alerts do not stop spending. Set provider daily quotas and a shared request budget before live calls.

ECR bootstrap is separate: create repository first in an isolated bootstrap stack or use a pre-existing ECR repository. Build and scan the reviewed image, push immutable tags, resolve its digest, then supply `image_digest_uri`. This avoids relying on an image in a repository that does not yet exist. Do not use routine targeted Terraform applies. Review private endpoint access and ECR pull permissions if using an external repository.

The Terraform provider lock is generated by `terraform init`; review and commit `.terraform.lock.hcl` before shared use. Create exact dependency locks and pin base/container/action digests after review. CI currently uses versioned action tags; digest pinning is a production gate. Run secret, IaC and container scans and retain SBOM and signed image evidence. Terraform changes are manually planned/applied; CI never auto-applies infrastructure.

## Release gates

1. Required CI, real-agent evaluation, threat/privacy review, provider usage accounting and staging rollback drill pass. Require branch protection and independent PR review.
2. Create GitHub `production` environment with required reviewers and main-only rules. OIDC trust must constrain `aud=sts.amazonaws.com` and exact `repo:OWNER/REPO:environment:production`. Configure a short-session role limited to ECS describe-task-definition, CodeDeploy create-deployment on this app/group, and required supporting read permissions. Terraform deployment uses a separate privileged role. No long-lived AWS keys in GitHub.
3. Set `AWS_RELEASE_ROLE_ARN`, `AWS_REGION`, `DEPLOY_APPLICATION`, `DEPLOY_GROUP` environment variables. Register the reviewed task revision from the existing definition, preserving IAM, secrets, logging and network configuration; change only approved fields and the image digest. Save previous task ARN, image digest, policy version and deployment ID in the gate record.
4. Dispatch release with the task ARN and evidence URL. Script validates digest and rejects demo config. Evidence review is enforced by environment reviewers, not by the URL itself. Green tasks start with traffic stopped for up to 30 minutes. Validate green via a private staging/test route or VPC runner; no public test listener is provisioned. Check auth, guardrails, provider health, usage, latency and no sensitive telemetry. Staff explicitly call `aws deploy continue-deployment --deployment-id ID --deployment-wait-type READY_WAIT` after evidence review.
5. CodeDeploy shifts 10% for 5 minutes then the remainder. Both target groups have 5xx alarms that stop and roll back on the first observed 5xx in a minute. These deliberately conservative alarms need tuning after staging. Wire custom policy-failure, latency and usage alarms before production. Use synthetic requests because low traffic can hide failures. Remain on-call through the canary and 30-minute observation period.

## Rollback and stop

During a deployment: `aws deploy stop-deployment --deployment-id ID --auto-rollback-enabled`. Confirm the rollback deployment succeeds, previous task/image is serving, auth and policy checks pass, alarms recover, and usage reconciles. After a successful release, dispatch a new deployment using the retained previous task ARN (review policy compatibility and the same release gates). Never restore an old vulnerable policy without policy-owner approval. Terraform ignores task revision and listener/target association managed by CodeDeploy; do not force those fields back with Terraform.

For provider cost runaway: disable provider key/quota first; restrict API ingress or scale ECS desired count to zero with the incident role; cancel active provider jobs; reconcile outstanding reservations and invoice records. Scale-to-zero does not stop ALB/NAT fixed costs. For policy leakage: block ingress, preserve metadata-only evidence and restrict access; rotate exposed credentials; involve policy and security owners. Do not copy raw prompts into public logs. Audit records currently contain request ID and outcome only; add durable approved decision metadata before launch.

## Verification responsibilities

CI runs unit/fault/API tests, demo eval, lint, dependency audit, Docker build, Terraform format and validation. AWS plans, actual image execution, security scans, IAM/OIDC boundaries, provider behavior, monitoring export and live rollback require staging evidence. No claim that local parsing validates AWS provider behavior. Never call the initial scaffold production-ready merely because local tests pass.
